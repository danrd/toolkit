# toolkit

Коллекция независимых вспомогательных модулей и скриптов для личных
проектов - не единый пакет с одной точкой входа, а полка утилит, каждая
из которых используется отдельно, по мере необходимости из других
репозиториев (`lector`, `maestro`, в перспективе `arc-agi`).

## Содержимое

- `llm_kit/` - переиспользуемый LLM-пайплайн (сборка промптов, локальный/
  хостед инференс с fallback-цепочкой, resumable task-loop с логированием
  в wandb). Раньше жил вендоренной копией в `lector` и `maestro` по
  отдельности - теперь единственный источник истины здесь, оба репозитория
  ставят его как зависимость (`toolkit[llm-kit]`). Подробности и примеры
  использования - в [`llm_kit/README.md`](llm_kit/README.md).
- `scientific/extract_slides.py` - извлекает кадры смены слайда/графика
  из YouTube-видео (yt-dlp + PySceneDetect + дедупликация по
  перцептивному хэшу), а также транскрипт из субтитров (ручных или
  автоматических - тем же yt-dlp, без доп. зависимостей) и manifest.json,
  сопоставляющий каждый кадр с тем, что говорилось, пока он был на
  экране. Самодостаточный скрипт, зависимости ставятся отдельно (см. его
  собственный docstring) и не требуют остального репозитория.

`arc-agi` (`subsymbolic/`) держит собственную физическую копию
`llm_setup.py`/`llm_runtime.py`/`prompt_builder.py`/`llm_run.py`/
`logging.py`, обновляемую скриптом синхронизации из `llm_kit/`, а не
живой зависимостью - пока проект в активной разработке, цельность
(весь код читается в одном клоне) важнее избежания дублирования. Когда
всё стабилизируется, можно будет тоже перейти на `toolkit[llm-kit]`.

## Изоляция зависимостей

Модули здесь очень разные по назначению (обработка видео, LLM-инфраструктура
и т.д.) - установка одного не должна тянуть зависимости всех остальных.
Два случая:

- **Отдельные скрипты** (как `extract_slides.py`) остаются
  самодостаточными файлами: ленивые импорты внутри функций, явная
  проверка зависимостей на старте (`check_dependencies()`), список
  зависимостей документирован в собственном docstring скрипта - без
  общего requirements-файла на весь репозиторий.
- **Устанавливаемые модули** (`llm_kit`) живут за `pyproject.toml` с
  отдельным optional-dependency extra на каждый бэкенд
  (`toolkit[llm-kit]` - база, `toolkit[llm-kit-llama-cpp]`,
  `toolkit[llm-kit-vllm]`, `toolkit[llm-kit-openrouter]`,
  `toolkit[llm-kit-hf]`, `toolkit[llm-kit-logging]`) - тот же подход,
  что раньше был внутри самого `llm_kit`, только на уровень выше.
